# Wave 4 fixture lock-in

These manifests define small generated vectors and future failure/oracle cases for
each Wave 4 root. Inline `hex` and `utf8` fields are the complete fixture bytes;
formula recipes use zero-based `i` and reduce values modulo 256. SHA-256 values are
over the exact generated bytes, not names, paths, TOML, or previously stored hashes.

All inline data is generated for this project or is a short factual interoperability
vector with its upstream provenance named in the owning manifest. It contains no
copyrighted game/audio dump, credential, private key, user archive, or private
provider response. Later children may materialize generated artifacts in temporary
directories, but must retain these recipes and compare exact expected results.

External qualification is opt-in and never changes the synthetic expected results:

- `JUNK_COLLECTOR_W4_CD_DUMP_ROOT` points to a user-owned Redumper/CD fixture root.
- `JUNK_COLLECTOR_W4_KEYCHAIN_TEST=1` enables a macOS Keychain round trip that uses
  a test-only service/account and cleans it up.
- `JUNK_COLLECTOR_W4_LAN_TEST=1` enables the recorded real-LAN/mDNS matrix.
- `JUNK_COLLECTOR_W4_TAILNET_TEST=1` enables the separately recorded tailnet matrix.

Missing variables mean “externally unqualified”, not passed. Tests must not print,
archive, copy, or hard-code the supplied root or any secret discovered through it.

For D05, copy `d05/oracle.example.toml` to `oracle.toml` in the owned fixture
root and replace every placeholder with independently recorded normalized layout
JSON SHA-256 (source identities replaced by their manifest-relative names),
AccurateRip outcome/offset, and per-track ARv1/ARv2 values. List every package file
in deterministic package order and keep the dBAR reference response under the same
private root. Then run `python3 scripts/run_d05_real_dump_oracle.py`. The runner
uses the production CUE/redumper readers and shared bounded verifier, reads no path
outside the supplied root, and does not print or copy the root or payload bytes.
An unset variable, missing manifest, placeholder, mismatched output, unsupported
layout, or unavailable reference response fails qualification; it is never treated
as a pass. The repository does not currently contain an owned dump or completed
external reference manifest.

Run `python3 scripts/check_wave4_fixtures.py` from the repository root; the
architecture check also invokes it. The checker parses every TOML file, regenerates
each declared inline/formula/composite byte vector, and checks length, SHA-256 and
any declared SHA-1/CRC32. It rejects unknown recipe syntax rather than evaluating
arbitrary formulas. Child-specific semantic oracles are
run only by the owning implementation child.

These manifests are a seed inventory, not completed semantic acceptance tests.
In particular, D06 separates test-supplied identity evidence from provider search
scores, and S04's incomplete transition is a negative parser fixture. D04 now
includes exact generated XML/text DAT bodies alongside the D04.1 game-format
vectors. D05 must add complete redumper/dBAR and offset oracles, and D07 must
generate the encoder goldens. Those fixtures cannot be marked passed because the
seed-byte reproduction check passes.
