# Junk Collector v0.1.0-beta.17

This beta fixes three purchased-audio compatibility problems and lets failed
identification retry after originals have already been preserved. Collector core
and media update together; Trash Amp is unchanged.

Integer PCM WAV accepts empty zero-padded 40-byte format chunks. MP3 decoding
includes the upstream empty-channel correction. APEv2 suffix text and front
artwork are supported, with checked tag boundaries excluded from audio decoding
and seeks. Originals are retained byte for byte; no files are repaired or rewritten.
Twelve observed inbox WAVs have contradictory declared lengths and still fail
visibly. This does not expand support to float/multichannel WAV or other codecs.
See [validation and limits](../validation/audio-compatibility-2026-11-01.md).

After updating, open **Review import → Retry this step** for a failed **Identify
files** step. The same Job validates and analyzes its archived originals without
another preservation Capture. Existing manual metadata survives. Originally
requested automatic FLAC preparation resumes after successful identification.
Retries are explicit; the update does not start a production batch automatically.

This release also includes improved inbox selection: aligned folder controls,
scoped bulk selection with mixed-state feedback, and package review in a popup.
See [selector acceptance](../validation/import-source-selectors-2026-11-01.md).

## Upgrade and rollback

Use `ghcr.io/aberrantwolf/junk-collector:v0.1.0-beta.17` or the immutable reference in
`release-image.json`. Update core and media together, retaining configuration,
ServerId/TLS, accounts, grants, Jobs, imports/scratch, archive and Bridge state.
No new enrollment or data conversion is required from beta.16. Do not rerun setup.
First adoption from beta.13 or earlier still requires documented offline
[archive enrollment](../../deploy/container/README.md#update).

Pull before downtime, stop all writers and retain a complete consistent recovery
point. Fi's local state/config and remote archive require a matching stopped-writer
recovery pair, with old images and the stack definition. After new writes, rollback
restores both members together with writers stopped. See the
[remote archive runbook](../../deploy/container/remote-archive.md).
This prerelease advances `preview`; stable `latest` remains unchanged.
