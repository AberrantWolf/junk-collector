# Junk Collector v0.1.0-beta.13

Library summaries are now prepared in the background when inventory, metadata,
artwork, preparation or audio results change. A separate bounded worker also
repairs missing summaries at startup/reindex and prepares new role/language
variants without waiting for a Library visit. The first Library request no longer
runs the detailed album resolver.

Library immediately returns basic entry rows if a summary is still updating.
Artwork and audio conclusions appear when the summary is ready; stale results are
not displayed as current. Pending/retrying pages refresh automatically, including
empty playback-attention results. Failed rebuilds retry without blocking peers.
File/playability/listening filters also use values projected at data changes.

Current authorization, role-based artwork privacy, language preferences and source
generation fences remain enforced. Summaries survive unchanged restarts. Obsolete
variants are pruned against actual current account/grant/preference demand, avoiding
eviction churn when more than twelve variants are needed. Import progress stays
live, and opening details still loads a fresh authorized Item.

## Installation and recovery

Use `ghcr.io/aberrantwolf/junk-collector:v0.1.0-beta.13` or the immutable digest in
the published `release-image.json`. This prerelease advances `preview`; stable
`latest` is unchanged. Update core and media together, retaining configuration,
identity/TLS, archive, private state, mounts and media sockets. Do not rerun setup.
Reload existing Library tabs to load the pending-summary display.

The additive upgrade backfills lightweight basic rows and adds disposable retry
state without forcing a catalog replay. Background preparation of existing full
summaries starts automatically. Catalog record, portable archive and private-state
formats remain unchanged. Originals, manual metadata, accepted evidence and queued
user jobs are retained; deployment starts no new verification batch.

Retain the old image and a complete stopped-server recovery point using the
[existing snapshot procedure](../../deploy/container/snapshot-recovery.md). Rollback
uses that matching complete recovery point and old image.
