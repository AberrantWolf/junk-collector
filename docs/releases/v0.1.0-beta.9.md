# Junk Collector v0.1.0-beta.9

Metadata now puts the active MusicBrainz release first, marks it as currently in
use, and places **Submit Disc ID to MusicBrainz** beside that release. Manual
field overrides remain visible. Submission still opens MusicBrainz for your
review and confirmation; it is descriptive metadata, not catalog/audio verification.
Metadata, playback, import and recovery guidance is shorter and easier to scan.

Development checks now select coverage from the complete change. Reviewed
text-only edits omit unit tests, short browser smoke takes about five seconds,
and beta candidates can run affected journeys. RC/stable functional qualification
remains full. The shared browser harness avoids the known macOS launch context
that aborts Chrome and bounds cleanup of owned processes.

Packaging caches Rust dependencies, overlaps source checks with native image
builds, and reuses validated source evidence. Deployment images remain release
builds. Publication promotes the exact validated AMD64/ARM64 exports without a
second compilation. See [testing](../testing.md) and its
[qualified delivery](../validation/testing-and-packaging-2026-10-26.md).

## Installation and recovery

Use `ghcr.io/aberrantwolf/junk-collector:v0.1.0-beta.9` or the immutable digest
in this release's `release-image.json`. This prerelease advances `preview`;
stable `latest` stays unchanged. Update core and media together with retained
configuration, identities, mounts and media sockets. Do not rerun setup.

Retain the previous image and a complete stopped-server recovery point for
archive, private state and configuration/TLS using the
[existing procedure](../../deploy/container/snapshot-recovery.md). This release
adds no archive-format conversion. Roll back with the matching complete recovery
point and old image. No Trash Amp installation is included.
