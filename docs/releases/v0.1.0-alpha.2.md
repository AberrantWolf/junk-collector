## Images and channels

The published version is `ghcr.io/aberrantwolf/junk-collector:v0.1.0-alpha.2`.
The workflow builds linux/amd64 and linux/arm64 and checks version/source labels,
manifest digest and anonymous downloads/pulls before promoting a moving channel.
Prereleases use **`preview`**; stable releases alone use **`latest`**. An older
release run cannot move its channel below a newer published version in that channel.
Moving channels require deliberate pulls/redeploys; no automatic update agent is added.

Download the installation bundle and `release-image.json` from a successful release.
The bundle defaults to the recorded manifest digest, not a moving tag. Keep that
record and the previous image/digest with the recovery point. A version tag is a
convenient selector; the recorded digest is the recovery coordinate. The verified index is `sha256:f86f46d2c8870f8d647fc9225ce2cfe7c4319521a29c89897b419abb77629433`;
version and `preview` select that index. `latest` was not created.

Empty-input manual dispatch builds/verifies an OCI export without registry
publication or channel changes. That dry-run bundle retains source-build instructions
and a local image setting; it is qualification output. An explicit retry of an
existing published release freezes its tagged source and repeats the publication
gates, producing a public digest-pinned bundle after anonymous checks pass.

## Storage and update/rollback classification

This is prerelease evolution, with no promise that an older image can open later
writes. In particular, automatic intake group titles can be stored as null rather
than an older manual string; an older server may not understand later workflows.
There is no checkpoint-stability wrapper or automatic deletion/compaction introduced
by the release packaging. Optional explicit stopped-server conversions retain their
own backup/inspection requirements.

Before updating, retain the old image and one **complete consistent** archive,
private-state/scratch and config/TLS point. Use the qualified
[Btrfs/incremental procedure](../../deploy/container/snapshot-recovery.md) where its
single-root eligibility applies, or the existing full CLI backup/validation fallback.
The packaged local backup area is `${COLLECTOR_DATA}/backups`; full backup is an
explicit operation that includes media. Independent copies and integrity checking
follow operator policy; no automated multi-terabyte backup or paid cloud service is
required. A local snapshot provides rollback, not protection against loss of its
device. Do not restore only SQLite/config or downgrade
only the image after newer writes; restore a whole matching old point into empty
roots, keeping the original server stopped.

The actual published-image NAS upgrade drill used the named `grouped-fix-20261019`
starting image and alpha.2, not the original alpha.1 source tag. A direct alpha.1→alpha.2
upgrade has not been qualified. Test recovery of any different starting installation
before adoption. Existing accounts/config must not be reset by fresh setup or sample
config replacement during an update.

## Limits before a supported release

Public images, both-platform anonymous pulls, Portainer service-targeted update and
Collector-only forced re-pull/redeploy are qualified. The live installation was
inspected only; temporary NAS roots supplied install/update/recovery acceptance. No automatic media-backup schedule
or backup-age reminder is implemented; independent storage is optional and does
not block release. Full public-ingress security and remaining
system-trusted second-device/native/format qualification retain their named limits.
No power-loss, all-format catalog verification, gapless/bit-perfect or unsupported
codec claim follows from these tests. See the authoritative remaining-work queue.
