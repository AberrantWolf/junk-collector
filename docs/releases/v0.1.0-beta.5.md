# Junk Collector v0.1.0-beta.5

Optional direct HTTPS music delivery keeps login, library control and grant
issuance on the existing Cloudflare hostname while audio uses a separate DNS-only
endpoint. A separate `collector-media` executable/container has read-only archive
access, no IP networking and a restricted Unix-socket connection to core.

## Changes

- Browser lock-screen/Now Playing metadata supplies track title, album artist,
  album and available artwork. Standard OS playback/track/seek controls use the
  existing player. Actual iPhone metadata rendering awaits the updated release;
  the earlier locked-screen playback acceptance did not cover this new metadata.
- Scoped media capabilities support browser and native HTTPS playback, ranges,
  seeking and live authorization checks. The web player prefers private media,
  then the configured direct endpoint, while control-origin music stays disabled.
- `/remote-media` tests a fresh challenge and, with a track queued, early/late
  source ranges. The operator confirms audible iPhone Safari cellular playback,
  seeking, next/previous and a track change while locked on the deployed source
  candidate. Extended sessions and network changes remain unqualified.
- The installation bundle includes the separate media service, Caddy HTTPS
  frontend and setup/rollback instructions. Caddy handles public certificate
  issuance and renewal; DNS and port forwarding remain explicit operator setup.
- LAN discovery prioritizes the selected private address and ordinary interfaces
  before Docker bridges, preventing container addresses from crowding out the NAS.
- Synology setup documents existing-directory requirements, CPU affinity when
  CFS quotas are unavailable, and unsupported process-count limits. Qualification
  uses disposable data and preserves diagnostics/cleanup when setup fails.
- The release workflow publishes the exact previously validated AMD64/ARM64 OCI
  images, retaining provenance instead of rebuilding during publication.

## Installation and update

The versioned image, available after publication succeeds, is:

```text
ghcr.io/aberrantwolf/junk-collector:v0.1.0-beta.5
```

`preview` advances to this prerelease after anonymous pulls and both-platform
checks pass. Stable `latest` is unchanged. Use the verified digest from the
release's `release-image.json` for an immutable installation.

Retain the old image and a consistent stopped-server recovery point covering
archive, private state and config/TLS. Follow the existing
[snapshot/update procedure](../../deploy/container/snapshot-recovery.md);
preserve mounts, account state, inbox groups, identities and working LAN binds.
Do not rerun account setup or replace retained configuration with examples.

Direct HTTPS media is opt-in: follow [media setup](../../deploy/container/media.md)
for the separate hostname, read-only/no-network service and public HTTPS frontend.
Verify the chosen NAS port is unused before forwarding WAN TCP 443 to it; NAS
port 9443 may already serve Portainer. Never forward a management listener.
Existing deployments without `[remote_media]` keep their private media behavior.

For an installation already running the source candidate, update **both Collector
and media** to the same verified release image. Keep Caddy pinned, existing
socket volumes, DNS/router settings and media configuration. In a Portainer stack
with Cloudflare or other companions, pull the chosen image first and update only
the changed services; disable whole-stack forced re-pull/redeployment.

Private schema remains **21** and catalog schema remains **15**. No storage
conversion is introduced. Restore the complete recovery point with its matching
old image when rolling back after writes.

## Boundaries and qualification limits

The media mount prevents mutation through that view; it does not hide mounted
archive contents after media compromise. Containers share the host kernel and
Docker daemon. The networked Caddy frontend requires its own host/DMZ policy to
restrict LAN egress; media's no-network setting does not supply that boundary.
Direct exposure also exposes the home Internet link to denial of service.

Source and actual-NAS acceptance are documented in the
[source tests](../validation/direct-https-media-2026-10-23.md) and
[deployment/device report](../validation/direct-https-media-nas-2026-10-23.md).
Public initial certificate issuance is qualified; later renewal, extended
background/lease boundaries, network transitions and deployment rollback remain
separate acceptance. The NAS kernel enforces CPU affinity and memory limits but
discards the requested process-count cap.

Trash Amp must consume the matching shared client in its next build to use direct
media. Publishing this server release does not install or rebuild Trash Amp.
