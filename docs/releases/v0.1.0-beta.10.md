# Junk Collector v0.1.0-beta.10

CD audio checking now offers **Check this disc with AccurateRip**. One durable
workflow records missing structure, fetches the matching response and checks the
audio. It resumes after restart and supports cancellation; only matching audio
becomes verified. No database data, mismatches and inconclusive searches remain
unconfirmed. Original files and manual metadata retain their authority.

**Administration → Library settings** saves per-music-collection automatic ingest
checks (enabled by default) and the maximum offset. **Check unconfirmed rips**
starts a bounded batch for existing originals. Accepted imports retain their frozen
defaults; existing unfinished imports retain their previous policy. FLAC/MP3
file-audio imports do not acquire CD checks. **Server settings → Background
workers** saves processing and inbox-copy limits immediately; running jobs finish
when limits shrink, and saved overrides survive restart and reindex.

Album rows show neutral **Import in progress** while uploading, publishing,
enriching or preparing audio. Playback-attention filtering resumes after that work
settles. Original Cover Art Archive images now stream through the existing
acquisition pipeline with a 128 MiB transfer bound. Automatic cover selection
compares standalone front covers and freezes its choice across restart. Image
allocation/dimension bounds remain independent, and dismissed historical lookup
failures stay dismissed when reopening Metadata.

The standalone `scripts/rip-cd.sh` retains its raw package and selected drive,
refines only initial SCSI/C2 errors and offers `--auto` generated folders with
optional bounded catalog-number naming. Q-only refinement remains optional under
the documented home-lab policy. The new `collector-cd-identity` utility reuses
shared TOC/disc-ID libraries without reading audio. Build that operator utility
as documented in [capture instructions](../getting-started.md#import-options);
it is separate from the NAS core/media container. Missing tools, ambiguous or
failed lookups retain the generated capture folder. This descriptive naming does
not verify audio or a physical copy. Naming failures report their specific cause;
successful captures eject the selected drive even when naming falls back. Failed
captures stay inserted, and eject errors are reported separately. Physical capture/live naming qualification
remains separate from the passing offline fixtures.

## Installation and recovery

Use `ghcr.io/aberrantwolf/junk-collector:v0.1.0-beta.10` or the immutable digest
in the published `release-image.json`. This prerelease advances `preview`;
stable `latest` is unchanged. Update core and media together, retaining the
existing configuration, identity/TLS, mounts and media sockets. Do not rerun setup.

The release adds private operational settings and guided-workflow columns without
rewriting archive masters or existing evidence. Retain the old image and a complete
stopped-server recovery point for archive, private state and configuration/TLS
using the [existing procedure](../../deploy/container/snapshot-recovery.md).
Rollback uses the matching complete recovery point and old image. No Trash Amp
installation or automatic scan of existing NAS rips is part of the update;
start the explicit library batch when ready.
