# Junk Collector v0.1.0-alpha.3

This experimental prerelease packages the post-alpha.2 setup, recovery and intake
improvements. It remains a home-lab release with the qualified platform/format
limits in the [remaining-work queue](../remaining-work.md).

## Changes

- **Optional inbox cleanup:** after preservation and requested processing settle,
  the import requester can explicitly remove matching source files from Work &
  history. Sources stay by default. Background checks validate the archive copies
  and source identities/bytes; changed or extra content is retained. Cancellation,
  quarantine and durable per-file intents support interrupted cleanup and retry.
  New inbox admission pauses while cleanup runs. See [operator instructions](../inbox-cleanup.md).
- **Portable full archive export/import:** CLI commands transfer preserved originals,
  metadata, artwork, evidence, lists and unknown records into empty roots. The new
  installation receives a fresh identity and explicit access recovery; operational
  accounts, sessions and configuration are excluded. This is separate from full
  operational backup/restore. See [the export guide](../archive-export.md).
- **Numeric-IP HTTPS startup:** password and recovery flows work with IP origins.
  Passkeys still require an eligible DNS origin; IP startup does not weaken TLS.
- **Metadata save recovery:** a failed write no longer leaves the edited save stuck
  behind its previous command outcome. Temporary NAS permission and bounded
  archive-capacity failures have qualified recovery paths.
- **Bounded login limiter retention:** rejected aliases cannot grow retained identity
  state without bound. Account, peer and global thresholds retain their protection.
- **Release baseline:** Rust 1.99.1 is pinned consistently in development, CI and the
  Docker builder. Shared libraries keep their exact published Git pins.

## Install or update

The release workflow builds native **linux/amd64** and **linux/arm64** images at
`ghcr.io/aberrantwolf/junk-collector:v0.1.0-alpha.3`. After anonymous pull/source
verification, it promotes **preview** and attaches the installation bundle,
`release-image.json` and checksums. The bundle pins the verified manifest digest.
Stable **latest** does not advance to a prerelease. The dated
[publication record](../validation/container-publication-2026-10-21.md) records
actual build and isolated update outcomes; a source tag alone is not image acceptance.

Inbox binds remain **read-only by default**. Cleanup requires an intentional
`COLLECTOR_INBOX_READ_ONLY=false` setting plus host directory write/traverse rights,
followed by normal recreation. Write access never enables automatic deletion.
Existing custom Portainer binds keep their configured mode. Finish external copying
and editing before confirming cleanup; it cannot revoke an already-open writer.
Small private cleanup receipt directories can remain after payload removal.

Before updating, retain the old image/digest and a **complete consistent** archive,
private-state/scratch and config/TLS recovery point. Use the qualified
[Btrfs recovery procedure](../../deploy/container/snapshot-recovery.md) where eligible,
or the stopped-server full backup fallback. Private schema **21** adds cleanup
requests/progress; alpha.2 cannot open it. To roll back after new writes, restore the
whole matching old point into empty roots with its old image. Image-only downgrade
is insufficient. Existing users/configuration must not be reset with fresh setup.

## Scope and limits

Cleanup removes only the selected imported inbox files, never archive originals or
history. Retained quarantine inputs are external to archive/state backup. It is not
an archive compactor or a hostile-writer/power-loss guarantee. Portable export is
full, requires a stopped source and empty import roots, and may contain private
collection facts; it is not a redacted sharing export, delta or merge.

Prior physical Safari, native audio, public-origin and recovery evidence is reused
where unchanged. No new all-format, gapless/bit-perfect, large-library throughput
or physical-device claim follows from this packaging. Full backups remain explicit;
there is no automatic multi-terabyte/cloud backup or backup-age reminder. This
release's deployment checks use isolated fixtures and do not update production.
