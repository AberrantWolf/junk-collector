# Junk Collector v0.1.0-beta.11

Background audio processing now shares a cancellation check across raw package
reads, CPU checkpoints and catalog parsing, polling durable Job state at most once
per second during those operations. This removes per-sector database polling that
could contend with Library reads during batches of AccurateRip checks. Publication
still checks cancellation and authority directly. Cancellation remains visible as
**Cancelling** while the worker stops. Audio algorithms and verification coverage
are unchanged.

Metadata review offers **Upload manual cover art** beside **Cover choice**. Original
PNG/JPEG/WebP images, visibility and alternative text are preserved; the upload
appears immediately among saved images for **Use selected artwork**. Unsaved cover
choices survive background polling. Unconfirmed uploads retry with the same frozen
inputs and command identity through the shared attachment form.

AccurateRip batch result pages omit excluded entries before pagination, including
older batches, while preserving summary counts and frozen membership. Eligible
pending and completed results remain visible; other batch kinds retain their
existing member views.

## Installation and recovery

Use `ghcr.io/aberrantwolf/junk-collector:v0.1.0-beta.11` or the immutable digest in
the published `release-image.json`. This prerelease advances `preview`; stable
`latest` is unchanged. Update core and media together, retaining configuration,
identity/TLS, archive, private state, mounts and media sockets. Do not rerun setup.

There is no new archive/private-state format or data conversion from beta.10.
Queued and interrupted running jobs remain durable across the update. An unfinished
AccurateRip computation may repeat the current disc's calculation; committed
observations are reused. Cancelled/failed jobs are not silently restarted.

Retain the old image and a complete stopped-server recovery point using the
[existing snapshot procedure](../../deploy/container/snapshot-recovery.md). Rollback
uses that matching complete recovery point and old image. No original media is
copied or hashed merely for the update, and no new library batch is automatically
submitted by deployment.
