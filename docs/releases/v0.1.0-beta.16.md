# Junk Collector v0.1.0-beta.16

> Deployment identifiers are anonymized; dates, source identities, outcomes and qualification limits are unchanged. Example addresses are not deployment instructions.

This beta improves digital soundtrack folder discovery, including Steam downloads.
Collector core and media update together; Trash Amp is unchanged.

Exact case-insensitive `FLAC`, `MP3` and `WAV` folders use their parent album name
and include parent covers, booklets and other companions. Numbered Disc/CD folders
work above or below the format folder. Separate albums, named OST/DLC sections,
raw-disc packages and alternate encodings remain distinct. Sibling encoding
packages have format labels in review; original relative paths and file order
are retained.

Files inside an encoding folder stay with that version. Shared parent companions
are retained once: with unwrapped tracks if present, otherwise FLAC before MP3
before WAV. Booklets and receipts retain curator-only defaults. Review can attach
versions to the same album explicitly. Decorated folder names such as `FLAC 24-bit`
are not guessed. Existing archived imports are not regrouped or rewritten.
See [workflow and limits](../digital-purchases.md) and
[source acceptance](../validation/format-folder-discovery-2026-11-01.md).

## Upgrade and rollback

Use `ghcr.io/aberrantwolf/junk-collector:v0.1.0-beta.16` or the immutable reference in
`release-image.json`. Update core and media together, retaining configuration,
ServerId/TLS, accounts, grants, Jobs, imports/scratch, archive and Bridge state.
No new enrollment or data conversion is required from beta.15. Do not rerun setup.
First adoption from beta.13 or earlier still requires documented offline
[archive enrollment](../../deploy/container/README.md#update).

Pull before downtime, stop all writers and retain a complete consistent recovery
point. application-host's local state/config and remote archive require a matching stopped-writer
recovery pair, with the old images and stack definition. After new writes, rollback
restores both members together with writers stopped. See the
[remote archive runbook](../../deploy/container/remote-archive.md).
This prerelease advances `preview`; stable `latest` remains unchanged.
