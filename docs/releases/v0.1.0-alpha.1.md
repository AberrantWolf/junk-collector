# Junk Collector v0.1.0-alpha.1

Experimental source prerelease for local evaluation and reproducible Rust builds.
This is a tagged checkpoint, not acceptance of LA3/PJ1 or the full first release.
No prebuilt binaries or container registry images are supplied with this release.

## Available

- Game/CD inventory, guided and bulk imports, retained originals and evidence.
- Metadata/artwork review, supported DAT matching and CD processing.
- Optional FLAC preparation, browser playback, collection lists and playlists.
- Accounts, collection permissions, durable work, recovery and a stopped-server
  backup/restore runbook.
- `collector-client` for native consumers; shared algorithms use `junk-libs v0.1.0`.

## Build from the tag

```sh
git clone --branch v0.1.0-alpha.1 https://github.com/AberrantWolf/junk-collector.git
cd junk-collector
cargo build --release --locked -p collector-server
./target/release/collector-server setup
./target/release/collector-server doctor
./target/release/collector-server serve
```

Use Rust 1.95 or newer and the build prerequisites in [README](../../README.md).
Cargo fetches the pinned shared libraries; no sibling checkout is required.
The web UI is embedded. Optional encoders are configured separately.

## Rust consumers

```toml
collector-client = { git = "https://github.com/AberrantWolf/junk-collector", tag = "v0.1.0-alpha.1" }
```

Consumers needing `collector-server`, `collector-store`, `collector-app` or
`collector-providers` in integration tests should use the same Git URL and tag
for those crates too. Keep one source/version across the Collector dependency graph.
The tag is a source pin, not a promise of stable Rust or HTTP APIs.

## Qualification and limits

Recorded local checks cover the Rust workspace, Clippy, formatting, architecture,
web checks/build and browser journeys. Isolated source builds work without sibling
checkouts. A Linux ARM64 Docker build and non-root runtime checks cover setup,
web assets, login, certificate-validated HTTPS and container recreation with
persistent account/session/TLS state. See [validation](../validation.md).

Trusted second-physical-device acceptance, the remaining native GUI/failure matrix,
independent real-dump verification coverage, full deployment/scale qualification,
automatic discovery/failover, certificate rotation, portable export/migration and
complete native/offline clients remain open. Game identity, structural inspection,
integrity and audio verification are distinct evidence types.

Use disposable storage for initial evaluation. For existing data, stop the server
and back up archive, full private state and configuration/TLS before changes;
follow [the backup/restore runbook](../local-alpha-installation.md). No stable
upgrade or checkpoint-compatibility promise is introduced by this alpha tag;
actual data-preservation and recovery requirements still apply.
