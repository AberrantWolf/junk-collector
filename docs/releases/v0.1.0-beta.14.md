# Junk Collector v0.1.0-beta.14

This beta adds reviewed digital-album matching and safeguards for a later move to
local private state with a remote archive. It also works with the current
single-NAS storage layout; publishing this release does not approve migration.

## Digital album matching

Explicit discovery fingerprints original-file FLAC/MP3 albums, looks up AcoustID
recordings and MusicBrainz releases, and presents coverage, durations, artwork and
one-to-one track assignments for review. Complete unambiguous mappings can be
applied through the existing metadata workflow. Durable jobs support cancellation
and retry; source and metadata changes invalidate stale reviews. Raw masters and
manual metadata retain authority. Browsing and polling do not read audio.

A configured AcoustID application key is required. Live recognition with that key
and representative user-approved audio remains unqualified. Support is limited
to mono/stereo FLAC and MP3, up to 256 files. Partial or ambiguous matches remain
suggestions for the manual metadata tools. This release updates Collector only.

## Storage admission and interrupted work

Normal startup now requires a matching archive identity and private-state binding.
Missing mounts, a different archive and missing/empty established private SQLite
state fail closed. Runtime storage failures latch unavailable and preserve
recoverable work. Publication/recovery distinguish I/O errors from absent files;
archive publication staging remains on the archive filesystem. Fresh setup is an
explicit path with durable interruption recovery.

Independent state/config, archive and inbox host paths, read-only isolated media
access and guarded Linux mount/boot templates support later migration. See the
[remote archive runbook](../../deploy/container/remote-archive.md) for required NFS
semantics, reconnect, coordinated backup, paired rollback and approval criteria.
Actual Fi/NAS write/outage/boot and paired-restore qualification is still required.

## Upgrade and rollback

Use `ghcr.io/aberrantwolf/junk-collector:v0.1.0-beta.14` or the immutable digest in
`release-image.json`. Update core and media together. Preserve configuration,
identity/TLS, accounts, grants, jobs, uploads, imports, scratch, the complete archive
and existing mounts. Do not rerun setup or initialize a replacement archive.

**First adoption from beta.13 or an older installation requires offline enrollment.**
Pull the new image before downtime. Stop all writers and media, confirm their clean
exit, and make a complete consistent recovery point with the old image and retained
stack/config. Verify the actual existing archive and private-state roots. Run the
new image's `enroll-archive` command against those exact roots as the application's
user/groups, then start core and media with the same qualified image. Enrollment
records identity/binding; it does not qualify NFS or replace backup verification.
Use the retained configuration rather than a sample. See [update instructions](../../deploy/container/README.md#update).

The current NAS's complete stopped-server Btrfs snapshot can still cover its
single-root installation. After the local-state/remote-archive split, recovery
requires a coordinated archive plus complete local state/config pair, including
all `state/imports`. Rollback after any new writes restores the complete matching
pair and old image with all writers stopped; merely downgrading the container or
restoring only one side is unsafe. Retain the newer pair separately for diagnosis.
See [snapshot recovery](../../deploy/container/snapshot-recovery.md) and the split
runbook before restoring. This prerelease advances `preview`; stable `latest`
remains unchanged.
