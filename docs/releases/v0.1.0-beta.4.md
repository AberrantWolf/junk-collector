# Junk Collector v0.1.0-beta.4

Beta.4 adds automatic trusted private playback for Junk Collector web and the
updated Trash Amp client. It remains a prerelease for backed-up home-lab use.
Publication is gated on the Container release workflow, both native architectures,
real container smoke checks and anonymous image verification. Readiness and the
verified digest are recorded in [publication evidence](../validation/container-beta4-publication-2026-10-22.md).

## What's new

- Sign in at the usual Collector address. The web player prefers a pinned
  WebTransport media connection to a reachable private server. Browsers may ask
  for Local network access. No internal certificate import, private DNS override,
  manual LAN URL or helper is needed for this path.
- The updated Trash Amp client obtains private HTTPS trust through its enrolled
  control connection. Streaming and downloads preserve saved account/cache identity.
- Internal P-256 certificates are generated and renewed by the server. Browser
  media grants bind the exact origin, session and representation; every range
  checks current permissions. Transfers remain bounded and seekable.
- **Public media fallback defaults to disabled.** Cloudflare remains usable for
  login/library control, but loss of a private route does not send media there.
  No Tailscale integration, provider discovery or configuration is performed.

See [the implemented contract](../automatic-private-playback.md) and
[source acceptance](../validation/automatic-private-playback-2026-10-22.md).

## Image and Portainer update

The expected version tag, usable only after publication succeeds, is:

```text
ghcr.io/aberrantwolf/junk-collector:v0.1.0-beta.4
```

The release workflow publishes linux/amd64 (including Synology DS1522+) and
linux/arm64, verifies public anonymous pulls and pins the installation bundle to
the verified manifest digest. `preview` follows this prerelease; stable `latest`
is not advanced. The workflow must finish before the image is called ready.

1. Retain the current image digest and create a consistent stopped-server recovery
   point for archive, private state and config/TLS using the existing
   [snapshot](../../deploy/container/snapshot-recovery.md) or
   [backup procedure](../../deploy/container/recovery.md).
2. Keep existing mounts, credentials and configuration. Set `COLLECTOR_IMAGE` to
   the verified beta.4 digest or version tag and update the stack with image
   re-pull enabled. Do not rerun fresh setup.
3. Permit private clients to reach **TCP and UDP 9845** on the server firewall.
   Host-network Compose exposes the listener automatically; no Internet port
   forwarding is needed. Management on 9844 is unchanged.
4. Reload the web app, allow Local network access if prompted, then play and seek.
   **Trash Amp needs the updated client build** from its automatic-private-playback
   delivery. Older installed clients do not understand the new media discovery;
   their previous URL pointing to the public/client proxy may no longer stream
   because public media fallback is disabled. The Collector image alone does not
   install Trash Amp. Keep `remote_media_allowed = false` during qualification.

Private schema stays **21** and catalog schema stays **15**. No data conversion is
introduced by this release. Existing beta.3 grouping/recovery behavior remains;
rolling back after new writes requires the matching recovery point and old image.

## Qualification limits

The production integration tests cover real Chrome playback/seeking, wrong pins,
public-media refusal and live logout/source release, alongside native decoder,
download/offline, authorization and certificate-rollover tests. Both repositories'
workspace tests and strict checks pass. New-build NAS/work-Mac installation,
managed VPN/UDP restrictions and Firefox/Safari playback remain separate checks;
the earlier work-Mac experiment does not qualify the new binary on every device.

Initial discovery and browser grant renewal require the normal control connection.
Private reachability does not prove a physical LAN path, zero WAN use or ISP billing.
The manual LAN hostname remains a deployed stopgap until updated builds are
installed; no NAS deployment is performed by publishing this release.
