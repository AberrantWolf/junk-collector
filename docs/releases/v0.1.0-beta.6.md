# Junk Collector v0.1.0-beta.6

Library album rows now show when recorded whole-album playback needs attention.
Open the album for the reason, or select the album playback attention filter to
find incomplete or unassigned albums without trying Play album on each one.

- Readiness shares album/list eligibility and published track availability.
  Missing discs, unresolved originals and incomplete preparation remain actionable.
- Albums prepared entirely as Opus are recognized, including their retained
  source coordinates; FLAC is not required for a ready album.
- Filtering retains collection, search, sorting, scoped pagination and access
  controls. The browser follows empty continuation pages to find later matches.
- Browsing uses recorded observations without opening or hashing audio payloads.
  Readiness is separate from catalog/audio verification, device codecs and routes.

## Installation and update

After publication succeeds, use
`ghcr.io/aberrantwolf/junk-collector:v0.1.0-beta.6` or the immutable digest in the
release's `release-image.json`. The prerelease advances `preview`; stable `latest`
is unchanged. AMD64 and ARM64 images are published from exact-source validation.

Retain the previous image and a consistent stopped-server recovery point for
archive, private state and configuration/TLS using the existing
[snapshot/update procedure](../../deploy/container/snapshot-recovery.md).
Preserve mounts, identities, accounts, media socket volumes and working network
configuration. Update core and the optional separate media service to the same
release image. Do not rerun setup or replace configuration with examples.

This release adds no archive or database schema conversion. NAS deployment and
physical iPhone acceptance of the new warning/filter remain separate from source
and container validation. It does not rebuild or install Trash Amp.
