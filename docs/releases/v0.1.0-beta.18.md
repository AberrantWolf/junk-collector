# Junk Collector v0.1.0-beta.18

This beta adds progressive Library refresh, lazy album tracks and requested-byte
media reads. Counts and compact album pages load independently; refresh and retry
state stays in the client. Playback reads no longer hash an entire original before
serving the requested bytes. Read and premature-EOF failures remain visible;
recorded digests are not fresh integrity attestations.

Partially recognized digital albums can be completed with an explicit all-file
recording assignment and review. Automatic artwork resumes through the existing
metadata workflow while manual artwork and metadata retain authority.

Grouped imports establish all reviewed physical copies before the first package
freezes the album revision. Distinct copies with staggered staging no longer fail
because a sibling adds its reviewed copy; unrelated inventory edits still conflict.

Collector core and media update together. Installed Trash Amp is unchanged; its
layered-refresh work remains separately staged. No real hardware, phone or cellular
qualification is claimed by this release.

## Upgrade and rollback

Use `ghcr.io/aberrantwolf/junk-collector:v0.1.0-beta.18` or the immutable reference in
`release-image.json`. Retain configuration, ServerId/TLS, accounts, grants, Jobs,
imports/scratch, archive and Bridge state. No new enrollment is required from
beta.17. Do not rerun setup. Earlier archive-enrollment requirements still apply.

Pull before downtime, stop all writers and retain a complete consistent recovery
point. Fi local state/config and remote archive require a matching stopped-writer
recovery pair and the prior images/stack definition. After new writes, rollback
restores both members together with writers stopped. See the
[remote archive runbook](../../deploy/container/remote-archive.md).
This prerelease advances `preview`; stable `latest` remains unchanged.
