# Utoipa 6 maintenance cleanup — 2026-10-25

The user authorized this upgrade after reviewing and committing the accumulated
security fixes. Review checkpoint `e0ef5c8` includes the shared XML event-bound
correction, pinned to published `junk-libs` commit
`317517c430744e4f1196e30850b37b3f13c10560`.

## Changes and contract comparison

- `utoipa` 5.5.0 → 6.0.0, `utoipa-gen` 5.5.0 → 6.0.1 and `utoipa-axum`
  0.2.0 → 0.3.0. The latter replaces unmaintained `paste` 1.0.15 with `pastey`
  0.2.3. Existing `pastey` 0.1.1 through another dependency remains unchanged.
- The request body is now `RefOr<RequestBody>`; the existing upload/body-limit
  extension applies to inline bodies. The contract test still checks every
  generated request body's extension.
- The document remains OpenAPI 3.1.0. Utoipa 6 omits empty response descriptions,
  but [the 3.1 Response Object requires a description](https://spec.openapis.org/oas/v3.1.0.html#response-object).
  The server fills empty descriptions with HTTP reason phrases, preserving any
  supplied description. The HTTP contract test checks the document version and
  required descriptions on every inline response.
- Regenerated `api/openapi.v1.json` and `web/src/generated/api.ts` from the
  annotated routes/DTOs. Compared the JSON recursively with the generated
  checkpoint contract, allowing only response description changes and ordering
  of unordered schema alternatives/sets. All 155 paths, operations, schemas,
  media types and body-limit extensions match. All 580 previously empty response
  descriptions are now populated; nullable union order also changes in generated
  TypeScript. No hand edits to generated files are needed.
- Utoipa and its Axum adapter declare Rust 1.88 minimum; the existing CI/Docker
  toolchain is 1.99.1, so no toolchain adjustment is needed.

## Scope and limits

The audit checks known advisories and maintenance status, not every possible
application vulnerability. Review findings and prior XML/CHD/PEM acceptance are
retained in their dated records. Native checks run on this macOS host; physical
media/device and production deployment qualification are not implied. Primary
sibling working trees/lockfiles and unrelated NAS documentation edits are
preserved. No release image, publication or live deployment is included.
